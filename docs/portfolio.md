# Public work portfolio

Owners/managers open Reputation → Portfolio. Upload a JPEG, PNG or WebP, add a caption and a meaningful image description, and optionally link an active treatment. The upload is a **private draft**. Open the saved draft to review its exact pixels and text, then explicitly confirm permission from everyone shown and rights to publish the work. Nothing is published by default or included in the real seed data.

Private client-gallery storage permission does not authorize public use. This portfolio takes a separate upload and never accepts a private client-photo ID or automatically copies a client's images. Do not include personal contact details, medical information or private identifiers in the caption or description. The confirmation records the responsible authenticated operator and permission wording version; it is an operator declaration, not a qualified signature or an independently obtained model release.

The browser reduces camera files up to 15 MiB. The API independently accepts at most 512 KiB of JPEG/PNG/WebP input, rejects unsupported/animated/oversized images, decodes at most 16 million pixels and stores fresh orientation-correct JPEG pixels without EXIF/location metadata. Stored images are at most 1,024 pixels per side and 256 KiB; the shared normalizer allows two processing jobs at a time. The salon limit is 200 active draft/published images, about 50 MiB maximum pixel storage plus database overhead. Listings do not read binary image columns, and gallery thumbnails load lazily.

Caption and accessible description are required, up to 300 characters each. Changing either or the treatment link returns a published image to draft and clears its publication confirmation. Saving unchanged treatment links preserves their original name snapshot, including after a catalog rename/deactivation. New links require active treatments. The public gallery filters by treatment; its detail panel offers booking when the linked treatment is currently available in the public catalog. Inactive treatment links never create a booking button.

Publish, unpublish, metadata changes and erasure use optimistic versions. A stale panel preserves the operator's draft and cannot replace newer work: close/discard, reload, and review the latest content. Uploads use an actor-scoped immutable fingerprint/key; an unknown response retains the image, metadata and exact retry packet in memory and locks the fields until retry or discard/reload. Other uncertain changes may already have succeeded; reload their state before making a different change. Drafts and source image data are not written into browser storage.

Unpublishing immediately makes fresh public image requests return 404. Erasing requires an additional confirmation and removes the stored pixels, caption, description and treatment link. The original upload receipt remains and cannot restore the image, through either an old upload retry or SQL mutation. Existing backup copies follow the separate backup retention policy; already downloaded visitor copies cannot be removed here. Public metadata/image reads and web HTML use no-store caching. An already loaded page can retain its previous snapshot until reloaded.

Audit records contain IDs, versions, image size and publication wording version, not image bytes or personal captions. Mutations serialize on a dedicated portfolio capacity lock and reload the caller's permissions after waiting. The portfolio is separate from the generic offline replica. No social network publication, external image storage account or real salon photo is activated.

TDD verification covers separate permission, draft privacy, metadata stripping, exact upload recovery, stale revisions, publication withdrawal on edit, public image visibility, explicit erasure, immutable removed images, ordinary-client/staff denial, manager access, image/storage limits and inactive treatment snapshots. Browser workflows also verify treatment booking entry, Spanish deletion, axe, overflow and live action hit targets while a success notification is present. Synthetic flat-color images are used throughout.

Review creation/editing, photo editing and moderation ignore completion callbacks after their original editor has unmounted. A late server response therefore cannot close another record opened meanwhile. Three reproduced failing regressions cover this lifecycle independently of network speed.
