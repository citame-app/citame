# Appointment reviews

The account's Reviews tab lists elapsed completed visits, plus the account's previously reviewed visits if an outcome was later corrected. A client account can submit one review per visit, choose a public name, give 1–5 stars and write up to 2,000 characters. Publication permission is explicit. Booked treatment names are optional and off initially; they use the original appointment snapshot. Names/emails from the private client profile are never copied into a public review.

New and edited reviews are pending. Owners and managers use Reputation to read the exact content, publish it or hide it with a reason visible to the client. The team cannot rewrite a client's name, score or feedback. Moderation is manual and the public page identifies the salon as moderator. There is no automatic filtering of low ratings. Do not disclose private client or appointment information in a public reply (1,000 characters maximum). Editing a review clears the old reply and returns it to pending.

The public `/reviews` page includes only published reviews whose original appointments remain completed, elapsed and active, with active client profiles. Ratings and totals use this same eligibility filter and one database snapshot. A service filter includes only reviews where the client explicitly chose to share treatments; otherwise filtering would disclose a private treatment indirectly. Pagination is bounded (12 initially, up to 50 per API page). The salon limit is 50,000 review records, including withdrawn receipts. Existing active rows must not be silently deleted to bypass that bound; retention requirements need a separate reviewed operational policy.

Withdrawal erases the review's public name, score, body, moderation reason and reply. The private appointment, frozen service snapshot and submission receipt remain. Old create retries return the current withdrawn state and never republish it. A client may explicitly edit their withdrawn review and give publication permission again while the visit is eligible; it returns to pending. Withdrawal cannot erase copies visitors already made, and historical database backups follow the separate backup retention policy.

Creation uses an actor-scoped immutable request fingerprint and key, and a unique appointment constraint. Concurrent identical requests return one review; changed requests with the same key are rejected. Unknown responses retain the reviewed fields and retry key in memory, locking those fields until retry or explicit discard/reload. All changes use optimistic versions. A stale edit/reply/moderation does not overwrite another change: close/reload and review the current record. Drafts are not persisted in browser storage. Audit events contain IDs, versions and states, not the feedback, chosen public name, reason or reply.

Identity, original services and creation receipt cannot be rewritten in SQL. Mutations serialize on a dedicated review lock and reload the caller's permissions after waiting. Review operations do not take scheduling locks and are excluded from the generic offline sync replica. All API reads and web HTML use no-store caching; unpublication takes effect on a fresh request. Already loaded pages can display their prior snapshot until reloaded.

This is feedback from a completed appointment, not an assertion that a card purchase was independently verified. No real reviews are seeded. Browser fixtures use synthetic clients and appointments. Review invitations and provider/social integrations belong to the outstanding marketing/acquisition work; no external message is sent here.

Verification: contract and API tests cover consent, strict payloads, completed-visit ownership, future/closed outcomes, publication privacy, frozen names, filtering/aggregates, pagination, concurrent unknown-response recovery, withdrawal, stale edits/replies, immutable identity and live moderator demotion. Browser workflows cover light/dark mobile/desktop creation, uncertain response recovery, manual publication, replies, public treatment privacy, discarded drafts, Spanish withdrawal, axe and horizontal overflow.
