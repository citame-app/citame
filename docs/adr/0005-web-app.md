# ADR 0005: Web app (public booking, auth screens, client account)

Status: accepted (Phase 3b-1). The staff and owner dashboard is Phase 3b-2 and lands inside the `/admin` layout that already exists.

## Context

Phase 3a left a complete API. Phase 3b-1 delivers the first user-facing surface: a mobile-first public booking flow, sign in and sign up, and the client account area. The dashboard is a later phase, so the shell, routing and role guards must be ready for it.

## Decisions

### TanStack Start (SSR) in the Bun/Turbo workspace

`apps/web` is TanStack Start 1.169 on Vite 8 with React 19, TanStack Router, Query and Store, and Tailwind CSS v4. Turbo runs `typecheck`, `lint`, `test` and `build` for it like every other package (`dist/**` is the cached build output; `e2e` is an uncached task that depends on `build`). `routeTree.gen.ts` is generated by the Vite plugin and committed so `tsc` works on a clean checkout (Biome ignores it).

Production runs `bun apps/web/server.ts` (`src/server/web-server.ts`): `/healthz`, the API proxy, static files with immutable caching for fingerprinted assets, gzip, and finally the Start fetch handler (`dist/server/server.js`). It is dependency-free on purpose: no Nitro, so the server in the container is the same code the tests exercise.

### Same-origin BFF proxy

The browser only ever talks to the web origin. The web server forwards `/api/*` to the Hono API at `API_INTERNAL_URL`:

- `/api/auth/*` is forwarded unchanged (Better Auth is mounted at `/api/auth/*` in the API).
- every other `/api/<path>` becomes `/<path>` (`/api/services` -> `/services`).

Cookies are therefore first-party (host-only, `HttpOnly`, `SameSite=Lax`, `Secure` in production) and there is no CORS. Cookies, `Origin` and `Content-Type` are forwarded; every `Set-Cookie` is returned; redirects are never followed; hop-by-hop headers are dropped; an unreachable API becomes `502` with the stable error envelope.

The API's origin check still applies, so the web origin must be listed: `TRUSTED_ORIGINS` (Compose defaults it to `http://localhost:4173`; `BETTER_AUTH_URL` defaults to the web origin there too).

**`TRUST_PROXY` semantics.** The API reads the client IP from the **last** `X-Forwarded-For` entry when `TRUST_PROXY=true` and assumes exactly one trusted hop. The web server is that hop and **replaces** the header with a single entry, the visitor's address, so a visitor cannot choose the identity the API rate-limits. By default the visitor is the TCP peer. When an edge proxy you operate sits in front of the web server, set `WEB_TRUST_PROXY=true` and the visitor becomes the last entry the edge proxy appended. `X-Forwarded-Host` and `X-Forwarded-Proto` are set from the public request. Because `TRUST_PROXY=true` makes the API believe that header, the API must not be reachable by anything but the web server: Compose publishes it on `127.0.0.1` only.

### Typed API client and SSR session

`src/lib/api` builds every call from the `@sob/contracts` Zod schemas: responses are validated at runtime (`ResponseShapeError` if the contract is broken), non-2xx answers become `ApiError` with the stable error code (Better Auth's own bodies are mapped to `invalid_credentials`, `email_taken`, `weak_password`), `429` carries `Retry-After`, and a failed `fetch` is a `NetworkError`. TanStack Query owns server state with per-router clients (no cross-request cache during SSR).

The root route's `beforeLoad` loads locale, theme and the session (`GET /me` with the visitor's cookie) through a server function and caches it in Query (`["bootstrap"]`), so SSR renders the right HTML and client navigations do not refetch it. Sign in, sign out and profile edits update that entry and invalidate the router. The role is never trusted on the client: the API re-reads it on every request; the route guards (`resolveAccess`) only decide where to send the visitor. `/account/*` needs any signed-in role, `/admin/*` needs staff or owner (clients are sent to `/account`), anonymous visitors go to `/sign-in?redirect=...` (the redirect is sanitized against open redirects).

New public endpoints added for this phase (ADR 0003/0004 conventions): `GET /salon` (name, timezone, booking window) and `PATCH /me` (name, phone), with `phone` now returned by `GET /me`.

### Booking state

The whole selection lives in the URL (`services`, `staff`, `date`, `slot`, `slotStaff`), validated and sanitized by `validateSearch`. Steps are deep-linkable, back/forward work, a step cannot be entered before the previous ones are complete, and signing in mid-flow loses nothing. TanStack Store holds only what does not belong in a URL: the notes draft (mirrored to `sessionStorage`), the slot a visitor just lost, and the appointment just confirmed. `slot_taken` and `slot_unavailable` return the visitor to the time step with every other choice intact and a clear message; availability is refetched.

### Accessible primitives: Base UI

Base UI 1.9 for the two pieces that are hard to get right by hand (modal Dialog with focus trap, scroll lock and Escape; Toast with a live region). Everything else is native (`checkbox`/`radio` stretched over their labels, `fieldset`/`legend`, `radiogroup`), which gives correct keyboard, screen reader and mobile behavior for free and keeps the bundle small. Alternatives considered: React Aria Components (the most complete, including calendars, but larger and it brings its own i18n/date stack that would compete with our `Intl`-based layer) and Radix (one package per primitive, no first-class toast). Known quirk: Base UI renders the toast close button `aria-hidden` until the toast is focused; axe accepts it and the toast text itself is announced through the polite live region.

### Design system

Tailwind v4 tokens live in CSS (`src/styles/tokens.css`): color roles for light and dark, elevation, radius, and a type scale; one accent (a rose clay), warm neutrals, Fraunces (display) and Inter (text), both self-hosted through Fontsource, preloaded, no external font requests. `tokens.test.ts` asserts WCAG AA contrast for every text, border and focus-ring pair in both themes. Dark mode follows `prefers-color-scheme` and a manual toggle persisted in a cookie so SSR renders the right theme with no flash. `prefers-reduced-motion` disables animations globally. Touch targets are at least 44px.

### i18n

`en` (default) and a complete neutral, professional `es-AR` catalog, typed so a missing key is a compile error and parity (keys and placeholders) is asserted by a test. The locale comes from a cookie, else `Accept-Language`, is persisted by the switcher, and sets `<html lang>`. Dates, times, durations and money go through `Intl` in the salon's timezone and currency (`src/lib/format.ts`); the salon timezone comes from `GET /salon`, and visitors in another timezone get an explicit note.

### Testing

Strict TDD in three layers: pure logic and components with `bun test` (happy-dom, Testing Library; server code swaps Bun's native Web API back in because happy-dom follows browser rules such as forbidden `Cookie` headers), and Playwright end-to-end tests against the real stack (Postgres, Valkey, the API and the built web server) at a mobile and a desktop viewport, including axe checks (zero serious or critical violations) and keyboard-only completion of the booking flow.

## Consequences

- One more container (`docker/web.Dockerfile`, non-root, health-checked) and a `web` service in Compose; CI builds it and runs the Playwright job with real services.
- With `NODE_ENV=production` the API sets `Secure` cookies: browsers accept them on `http://localhost`, anywhere else TLS must terminate in front of the web service.
- Known gaps: no password reset or email verification (Phase 7), guest booking is out of scope (ADR 0003), the dashboard is a placeholder behind the final guards.
